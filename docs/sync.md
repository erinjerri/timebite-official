# Session reconciliation and transport gap

The shared session ID is a UUID generated at start. Pause, resume, and complete increment a revision. Completion is terminal; an older running or paused copy cannot resurrect it. `SessionReconciler` merges equal IDs, chooses a higher revision for nonterminal conflicts, and uses transition time for equal revisions. It rejects two distinct active session IDs rather than silently counting both. Completion of one ID is idempotent in the local store and is counted once in daily progress.

This is a conflict policy, not a working device transport. [Apple Watch Connectivity](https://developer.apple.com/documentation/watchconnectivity) only connects iPhone and its paired Watch. The current destination has no verified Mac–iPhone or iPhone–Watch relay, no offline delivery queue, and no cross-device ownership authority. The Watch target uses local storage, so Mac and Watch can diverge. Do not submit or describe it as a synchronized companion until a transport is implemented and disconnect/reconnect tests pass.

An iPhone relay would need to forward the same session snapshot/ID between Mac and iPhone and between iPhone and Watch, persist outbound changes for offline replay, merge incoming revisions, and publish the reconciled state back to both devices. Apple's [Multipeer Connectivity](https://developer.apple.com/documentation/multipeerconnectivity) can connect nearby Mac and iPhone but requires local-network privacy keys and is deprecated in favor of Network framework; neither path is present in the audited production source. A remote transport would need its own availability and account requirements. The shipping choice must be proven through fault testing, not selected solely from API availability.
