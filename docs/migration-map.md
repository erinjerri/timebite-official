# September 23, 2026 production migration map

`timebite-official` is the destination. The release slice is create action → start → live elapsed time and app-owned ring → pause/resume → complete → persisted progress. This is an evidence-based audit of locally accessible repositories as of September 15, 2026. Classification describes suitability for this release, not the quality of a whole repository.

The destination already has uncommitted `Package.swift`, `TimeBiteCore/`, `Tests/`, and documentation work. Preserve it and reconcile schemas before moving any source files. `TimeBite` and `timebite-beta` were not found as local directories under `Documents`; their code is **UNKNOWN**. The source repositories also have uncommitted changes; inspect their working-tree versions before any selective migration.

## Source repositories and confidence

`timebite-macos` is the best local Mac execution baseline, but the required paused state and cross-device sync are absent. `timebite-platform` contains shared presentation/domain ideas and an iOS app with SwiftData and experimental surfaces. `timebite-torus-agentbeats` and accessible CYRA repos are research sources. `timebite-official` currently has no shipping app targets. Exact-name `TimeBite` and `timebite-beta` sources remain unlocated; do not classify their implementations as dead or duplicate.

## Release gates before further migration

1. Reconcile destination Action with the Mac persisted Action schema without discarding existing user data.
2. Implement and test timestamp-based pause/resume, reconstruction, unique completion, daily boundaries, and ring clamping in the shared domain.
3. Confirm a working Mac app target and a Watch target, then determine whether any proven WatchConnectivity code exists.
4. Verify Mac and Watch runtime loop, offline/reconnect consistency, Health denial, clean install, and relaunch; document ten manual repetitions in `Docs/releases/2026-09-23.md`.
5. Build all four targets using Xcode. The shell currently selects `/Library/Developer/CommandLineTools`, so `xcodebuild` cannot run until the Xcode developer directory is selected for builds.

Apple documents [Watch Connectivity](https://developer.apple.com/documentation/watchconnectivity) specifically as communication between an iOS app and its paired watchOS app. `WCSession.isSupported()` is unavailable on other devices, including Mac. The September 23 Mac/Watch state requirement therefore has no direct WatchConnectivity implementation path; an iPhone relay and its Mac transport must be verified, or a different existing cross-device approach located.

No code is migrated on the basis of this map alone. Each source file must be inspected with its dependencies and tests before adoption.
